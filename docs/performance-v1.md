## What if 1a had auto-increment?

1a's op F is unused, enough for post-increment and pre-decrement loads and stores (`LDB r1, [r2]+`, `ST r1, -[sp]`). This estimate removes every `ADDI rB, ±size` that steps the base register of an adjacent `[rB]` load or store (within three instructions, nothing else touching rB in between) and charges the access the same cycles, as the model does for 1b. It's rough, and probably low: 1a code is often shaped around the short offsets instead (the VM reads operands at `[r8 + 1]`, `[r8 + 2]` and steps r8 once per instruction), and only a rewrite would show what auto-increment does there.
